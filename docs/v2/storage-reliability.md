# Report storage reliability

This documents the October 5, 2026 storage changes. The local cache problem is
separate from BigQuery scan bytes. No metrics, bucket thresholds, RCA formulas,
80 GiB query limit, report URLs, Mini Audit backend, scheduling or repository
location are changed by this work.

## Findings and consumers

The pre-change canonical weekly run **did generate both legacy and V2 HTML**.
`run_v2_release.py` called `weekly_market_report.py` with `--renderer both` for
all markets and Headout. All-market V1 is **one multi-market file**, not one
legacy file per market. Headout is another V1 file. V2 was rendered once there
and again by the combined gate after goals and OKRs; the second render overwrote
the first at the same paths. That was redundant computation/transient allocation,
not another permanent V2 set.

The normal path now calls `--renderer snapshots` and renders V2 only at the
combined gate. The shared CSEE/Nordics page is then rendered once, unchanged in
meaning. The V1 renderer code is retained as an explicit fallback.

The scheduled weekly prompt selects `run_v2_release.py`, not V1. The analytics
checkout still has an older explicit V1 producer; it is not the scheduled V2
entrypoint and was not silently rewritten. `bucket_diff.py` is a generic
operator-supplied HTML consumer, not a scheduled reason to pre-generate V1.
RCA helpers read their existing sources, not the redundant V1 render; exports
read snapshots. The consumer audit covers tracked weekly scripts/alerts/tests/
instructions, the related analytics scripts and monthly engine, and configured
weekly automation. It does not claim to discover unknown external/manual users.

Monthly uses V2 only. `run_market_monthly.py` formerly rendered a standalone V2
page, then `publish_ledger.py` rebuilt it with `MMR_LEDGER_HOME=/`. Now direct
`--publish` defers rendering to the publisher. `run_all_monthly.py --publish`
passes `--defer-render` through parallel data preparation, followed by one final
render during serial publication. A standalone non-publish invocation still
renders a standalone report as before. No stale prebuilt HTML is reused.

## Safe copy behavior

`report_storage.copy_independent` attempts `clonefile` on macOS. It verifies
source stability, full content hashes and different inodes, then atomically
replaces a staging destination and fsyncs it. Changing one file cannot mutate
its retained equivalent. Unsupported filesystems use a verified full copy;
disk estimates never assume cloning will save space. Symlink traversal is
rejected. This does not reduce Vercel's remote upload/storage bill.

Seeded notebooks remain complete physical directory trees from the operator's
perspective. No object store, route remapping or partial-manifest deployment is
introduced. Rewrites allocate new blocks, as they should. Mini Audit injection
still runs through its existing code, and identical latest/dated results are
cloned after final packaging. Some transient allocations during injection remain.

## Disk and concurrency contract

Both canonical release entrypoints use the weekly module, API version 1, and
the same `.cache/report_storage/writer.lock`. Missing/incompatible shared code
blocks monthly generation. An active weekly, monthly or retention writer blocks
another canonical writer. The lock file is never unlinked to bypass ownership.

The start requirement is `free >= max(20 GiB, 3 × baseline size) + 30 GiB`.
Non-deployed dependency/build caches are excluded from baseline estimation.
Each distinct data/notebook/temp filesystem is checked. Canonical steps recheck
space before work, and notebook seeding re-estimates against its source size.
Insufficient disk fails before queries/copies; the error reports available,
required, working and reserve bytes. No unverified reclaim estimate is credited.
No emergency deletion occurs. Canonical orchestration owns the writer lock;
lower-level tools must not be launched concurrently outside that contract.

## Fail closed retention

`storage_retention.py` is dry-run by default. Its candidate discovery is limited
to an independently backed-up and restore-verified manifest, never all old files
in a directory. Application requires the exact reviewed plan hash and a journal
outside the candidate cache. It is not enabled as an unattended delete job.

The registry must supply fresh production/rollback/monthly/recovery references,
explicit pins, hashed supporting evidence and a verified backup/restore receipt.
References expire after one hour. A candidate must be HTML in an explicitly
`closed_verified` duplicate-working artifact at least seven days after closure.
Its retained equivalent must be pinned, present, independently addressable and
SHA-256/size identical. Unknown, unfinished, unclassified, unique, non-HTML,
pinned or newly referenced files are blocked. Age alone is never eligibility.
Snapshots, receipts, journals, historical mappings, unique recovery files and
backend data are not candidates. Current production, previous two weekly
releases, latest monthly baseline and active recovery remain pinned in full.

Application holds the shared lock, recomputes the plan, rehashes each pair just
before removal, checks directory/file identity without following symlinks,
fsyncs an intent record, unlinks only the named file and fsyncs the outcome.
It never recursively deletes a directory. A retirement marker blocks a partially
pruned notebook from canonical staging/deployment. Original receipts remain
unchanged; restoration maps record original path, keeper, size and SHA-256.

`--resume` reconciles the same exact plan after interruption. Missing files must
have a previous intent plus surviving backup/keeper proof. It does not clear the
journal or expand scope. Fresh references are required even for recovery. Restore
retired payloads into a **new** staging directory and re-run complete preservation
checks; do not remove the retirement marker and blindly deploy the old folder.

The 60 GiB field is advisory reporting only. No code deletes additional files to
meet it. Permanent history means total storage cannot remain mathematically
constant forever. The objective is approximately linear unique-data growth,
bounded transient duplication and an enforced disk reserve—not deleting history.

## Measurements and growth model

After the separately approved first batch, cache remains approximately **86.11
GiB**. The storage code does not retroactively coalesce or delete the remaining
old copies. Rehearsal artifacts are outside that cache and are retained as recent
working evidence; APFS logical/allocated sums count shared extents repeatedly.

At September 27 and September 2026 payload sizes:

- Weekly producer HTML: 0.362 GiB; unique packaged HTML: 0.366 GiB; frozen
  snapshots: 0.425 GiB. Approximate incremental unique data: **1.153 GiB/week**,
  plus small sidecars/receipts. This conservatively retains raw producer HTML.
- Monthly final HTML: 0.280 GiB (17 reports); dated JSON: 0.172 GiB; CE-health
  cache payload: 0.031 GiB. Approximate incremental unique data: **0.483 GiB/month**,
  plus allocation/metadata overhead. Publisher and producer share their identical
  final HTML instead of allocating another 0.280 GiB.
- Four weekly runs + one monthly run: approximately **5.1 GiB** of unique data
  versus roughly **23–24 GiB** under repeated full-notebook copying. This is a
  model, not a measured future guarantee; datasets, new UI versions and repair
  runs can grow it. Without APFS cloning, full-copy fallback grows faster and
  the disk gate stops safely.

There is no honest fixed steady-state size while preserving all unique history.
Future immutable history can eventually require another storage tier; this patch
does not pretend pruning duplicates removes that requirement.

## Verification and rollout boundaries

`storage_rehearsal.py` uses explicit frozen snapshots, goals, OKRs and monthly
facts, and writes only to a new isolated output directory. It renders all weekly
and monthly scopes, compares full-copy and CoW publication byte-for-byte, runs
the weekly preservation gate and clones/verifies rollback. It does not call BQ,
Slack, Sheets, deployment APIs or the Mini Audit backend. Retention tests operate
only on disposable fixtures, including interruption, missing/changed keepers,
stale references, symlinks, active locks and scope tampering.

October 5 rehearsal: 18 weekly parity checks; 38 weekly URL files identical;
17 monthly reports identical; 374 frozen source files unchanged; 304 base/rollback
files unchanged; 285 weekly/API/history files preserved through monthly publish;
1,326 observed APFS clones. Existing unrelated monthly working-tree edits were
preserved; renderer comparisons use the same frozen inputs and renderer on both
sides, not unrelated historical report versions.

This is a local frozen-source end-to-end rehearsal, **not** a new fresh-BQ release
or a live Mini Audit read/write test. Local commits do not push, deploy, activate
pruning or sync the monthly analytics mirror. The monthly mirror must not receive
a broad sync of unrelated uncommitted source edits. Use the canonical entrypoint
with the matching weekly guard, or review that mirror update separately.
